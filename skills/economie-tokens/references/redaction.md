# Rédaction économe

## Réponses dans le chat

- Commencer par la réponse ou le résultat. Pas d'introduction, pas de reformulation de la demande.
- Ne pas raconter les étapes que l'utilisateur a vues passer ; dire ce qui a changé et ce qui reste.
- Une recommandation argumentée en une phrase, pas un tour d'horizon de 5 options.
- Liste ou tableau plutôt que paragraphes ; pas de titres pour une réponse de 5 lignes.
- Chemins et lignes (`fichier.py:42`) plutôt que recopier le code.
- Ne pas recoller un fichier entier pour montrer une modification de 3 lignes.
- Pas de formules de politesse finales ni de « dis-moi si tu veux que… » systématique.

## Documents, scripts, rapports

- Fixer la longueur cible avant d'écrire (« 1 page », « 300 mots », « 8 minutes de vidéo ≈ 1 100 mots »).
- Plan validé d'abord, texte ensuite : réécrire un plan coûte 10 fois moins que réécrire un texte.
- Retouches : éditer les passages visés, ne pas régénérer tout le document.

## Prompts pour d'autres modèles (sous-agents, génération d'images, API)

- Contexte nécessaire et suffisant : le but, les contraintes, le format de sortie, la longueur max.
- Exiger une sortie courte et structurée (« ≤ 10 lignes », « JSON {a,b} »).
- Pas de répétition de la même consigne sous trois formes.
- Exemples : 1 à 3 bien choisis.

## Code

- Le code demandé, pas plus : pas de variantes, pas de fonctions « au cas où », pas de README non demandé.
- Commentaires seulement là où le code n'est pas évident.
- Respecter le style existant : moins de corrections après coup.
